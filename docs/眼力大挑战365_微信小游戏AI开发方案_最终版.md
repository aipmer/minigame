## 0. 项目最终决策

### 0.1 项目定位

本项目是一款能力测试型休闲小游戏，核心玩法是：

> 玩家在限定时间内，从一组相似元素中找出唯一不同项，完成挑战后生成分数、等级、称号和好友排行。

项目品牌名称：

```text
休闲游戏365
```

首款游戏建议名称：

```text
眼力大挑战365
```

备选名称：

```text
眼力测试365
```

命名建议：

- 如果还未备案和提交审核，优先使用「眼力大挑战365」。
- 「眼力测试365」搜索心智更强，但「测试」二字可能带来工具类、视力检测、医学判断等审核误解。
- 页面文案可以保留「60秒眼力挑战」「找出唯一不同项」「观察力挑战」等表达。
- 不使用「视力检测」「色盲检测」「色弱测试」「近视判断」等表述。

## 1. 开发形态选择

### 1.1 最终选择：微信小游戏

本项目正式开发应选择：

```text
微信小游戏
```

不是普通微信小程序。

原因：

1. 项目核心是游戏循环，不是页面工具。
2. 需要实时点击反馈、倒计时、结算、好友排行、再挑战等游戏能力。
3. 已确定使用 Cocos Creator，技术路线天然对应微信小游戏。
4. 好友排行榜更适合使用微信小游戏开放数据域。
5. 后续扩展反应力、专注力、记忆力等系列玩法时，小游戏工程更可复用。

### 1.2 普通微信小程序的定位

普通微信小程序只适合做早期玩法原型，例如：

```text
1-3 天做一个低保真 Demo
验证 60 秒 10 题是否有趣
验证色块、方向、文字差异是否好识别
验证结果页文案是否有分享感
```

但不建议作为最终上线形态。

## 7. 游戏关卡设计

### 7.1 主模式：60秒眼力挑战

```text
每局 10 题。
总时长默认 60 秒。
每题难度逐步提升。
答对进入下一题。
答错扣 3 秒，并扣除少量分数。
连续答对可以获得连击加分。
```

### 7.2 首版题型

首版实现 3 类题型。

| 题型 | 占比 | 说明 | 是否必做 |
|---|---:|---|---|
| 色块明度差 | 50% | 在相似色块中找出明度不同的一格 | 必做 |
| 方向差异 | 25% | 在方向相同的箭头中找出方向不同的一格 | 必做 |
| 数字 / 文字差异 | 25% | 在相似数字或文字中找出唯一不同项 | 必做 |
| 形状差异 | 0% | 圆形、椭圆、三角形等形状差异 | 第二版 |

## 8. 题型细节

### 8.1 题型 A：色块明度差

规则：

```text
在一组颜色相近的色块中，找出明度略有不同的那个。
```

设计原则：

```text
使用 HSL 色彩空间。
只改变 L 明度，不改变 H 色相和 S 饱和度。
这样可以减少色觉差异带来的不公平，也避免形成色盲/色弱检测联想。
```

参数：

```text
gridSize：3×3 到 6×6
baseColor：随机 HSL 颜色
deltaL：明度差
correctIndex：目标格索引
```

首版难度建议：

| 难度 | 网格 | ΔL 明度差 |
|---|---|---:|
| 简单 | 3×3 / 4×4 | 12%-20% |
| 普通 | 5×5 | 6%-12% |
| 困难 | 6×6 | 3%-6% |

不建议首版把 ΔL 降到 1% 以下。不同手机屏幕和环境亮度差异较大，过低会让挑战变成「看不清」。

### 8.2 题型 B：方向差异

规则：

```text
在一组方向相同的箭头中，找出方向不同的箭头。
```

方向：

```text
上
下
左
右
左上
右上
左下
右下
```

示例：

```text
一堆向右箭头中，有一个向左箭头。
一堆向上箭头中，有一个向右上箭头。
```

### 8.3 题型 C：数字 / 文字差异

规则：

```text
在一组相似数字或文字中，找出唯一不同项。
```

示例：

```text
9999 中找 9998
8888 中找 8988
日 中找 目
土 中找 士
未 中找 末
己 中找 已
```

注意：

```text
不要使用复杂生僻字。
不要使用低俗、敏感或有争议文本。
文字必须保证清晰可读。
```

## 9. 关卡生成逻辑

### 9.1 数据结构

```ts
type QuestionType = 'color' | 'direction' | 'text';

type Difficulty = 'easy' | 'normal' | 'hard';

interface QuestionData {
  id: number;
  type: QuestionType;
  gridSize: number;
  correctIndex: number;
  baseItem: ItemData;
  diffItem: ItemData;
  difficulty: Difficulty;
}

interface ItemData {
  color?: string;
  hsl?: {
    h: number;
    s: number;
    l: number;
  };
  direction?: 'up' | 'down' | 'left' | 'right' | 'upLeft' | 'upRight' | 'downLeft' | 'downRight';
  text?: string;
  rotation?: number;
  scale?: number;
}
```

### 9.2 生成规则

```text
1. 根据题号确定难度。
2. 根据难度确定 gridSize。
3. 根据题号和随机因子选择题型。
4. 生成 baseItem。
5. 根据题型生成 diffItem。
6. 随机生成 correctIndex。
7. 渲染网格。
8. 点击 correctIndex 判定为答对。
```

### 9.3 10 题难度曲线

| 题号 | 网格 | 推荐题型 | 难度 |
|---:|---|---|---|
| 1 | 3×3 | 色块明度差 | 简单 |
| 2 | 3×3 | 方向差异 | 简单 |
| 3 | 4×4 | 数字差异 | 简单 |
| 4 | 4×4 | 色块明度差 | 普通 |
| 5 | 5×5 | 方向差异 | 普通 |
| 6 | 5×5 | 色块明度差 | 普通 |
| 7 | 5×5 | 数字 / 文字差异 | 普通 |
| 8 | 6×6 | 色块明度差 | 困难 |
| 9 | 6×6 | 方向差异 | 困难 |
| 10 | 6×6 | 数字 / 文字差异 | 困难 |

## 11. 动效与反馈

```text
点击正确项后：
- 当前格子轻微放大
- 出现绿色光圈
- 播放 correct 音效
- 显示 +10 分动画
```

```text
点击错误项后：
- 当前格子左右轻微抖动

- 播放 wrong 音效
- 剩余时间 -3 秒
- 当前题保持不变
```

### 11.3 结算反馈

```text
分数从 0 动画增长到最终分数。
等级徽章出现轻微弹性动画。
如果刷新最好成绩，显示「新纪录」。
```

动效原则：

```text
所有动效时长 <= 300ms。
游戏进行中不做复杂背景动效。
关卡切换使用轻微淡入淡出。
```

## 12. 微信开放数据域排行榜

### 12.1 排行榜范围

MVP 只做：

```text
好友最高分榜
```

### 12.2 数据字段

```text
score：挑战分
timeUsed：用时
accuracy：正确率
level：等级
title：称号
```

### 12.3 排序规则

```text
1. 挑战分高者排名靠前。
2. 挑战分相同，用时短者靠前。
3. 用时相同，正确率高者靠前。
```

### 12.4 展示原则

允许展示：

```text
好友榜第 X 名
好友最高分
好友昵称和头像
```

禁止展示：

```text
全国排名
击败全国 x% 用户
击败全网 x% 玩家
```

## 13. 激励视频广告设计

### 13.1 首版策略

首版可以只预留接口，不一定立即接广告。

如果接广告，只接：

```text
激励视频广告
```

不接：

```text
插屏广告
开屏广告
误触 Banner
答题中断广告
```

### 13.2 推荐广告位置

| 场景 | 是否推荐 | 说明 |
|---|---:|---|
| 再挑战一次 | 推荐 | 看广告后获得额外挑战机会 |
| 查看答案 | 可选 | 看广告后查看错题答案 |
| 复活继续 | 暂缓 | 测试型玩法里复活逻辑不自然 |
| 解锁困难模式 | 第二版 | 首版不做 |

### 13.3 广告降级逻辑

```text
广告加载失败：直接允许用户继续，不阻塞流程。
用户中途关闭：不给奖励，但必须正常返回页面。
非微信环境：自动跳过广告流程，方便开发调试。
```
